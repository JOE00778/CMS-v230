# 新品订货申请（page48）设计 · 2026-11-13

Boss 2026-11-13：「运营想要的货在 CMS 中自己提申请 → 采购确认 → 做发注书 → 每周确定一次 PO 是否到货」「主要用于新品的订货」
「不需要分角色，只要能看到，采购负责人就会去确认，如果一直不到就会一直提示」→ 方案 A「OK 执行」（超期默认 = 发注日 + 14 天）。

## 意图
新品到货率目标 ≥85%（2026-04 实绩 <50%，wiki org-process）。申请散在各处、订了不到没人盯 → 一页看全程，没到的一直挂着。

## 目标 / 非目标
- 目标：申请 → 确认 → NST 发注书 CSV → 到货自动跟踪（每天随 NST 同步）、超期置顶标红、到货率一个数。
- 非目标：角色权限（谁都能确认/取消，记录是谁）；飞书通知；直接写 NST（只出 CSV、人手导入）；改 page10/15 的功能。
- 反目标：同一 JAN 两个未完成申请互相抢同一张 PO（→ 有未完成申请的 JAN 不能再提）。

## 方案（Boss 选 A）
- **A 新页 page48「🆕 新品订货申请」（订货管理首位）** ← 选定：一页走完，复用飞书登录、NST PO 同步、page10 发注书逻辑。
- B 飞书多维表格做申请/确认、CMS 只跟踪：两个系统，且到货数据在 CMS。
- C 塞进 page10 一个 tab：page10 是一次性 CSV 工具，跨周跟踪的清单放不下。

## 数据
`sourcing.new_item_request`（页面首次加载幂等建表，同 page34）：
id · jan · item_name · qty · note · requested_by · requested_at · status(requested/confirmed/cancelled)
· supplier · unit_price · confirmed_qty · confirmed_by · confirmed_at · cancelled_by · cancelled_at。
发注/到货不落表，每次从 `nst.purchase_order_line` ⋈ `nst.item_master_raw`(internal_id) 按 JAN 现算。

## 判定（shared/new_item_request.py，纯函数）
- 对得上的 PO 行 = 同 JAN 且 发注日 ≥ 申请日（我的判断：采购可能先下单后点确认，用申请日不用确认日）。
- 状态：待确认 → 待发注（已确认、无 PO 行）→ 在途 / 部分到货 → 已到货（入荷数 ≥ 发注数）；
  PO 行全部关闭但没到齐 = 「PO 关闭·未到齐」（终态、不算到货）；取消 = 已取消。
- 期限：未到齐的 PO 行取 入荷预定日，没有就 发注日 + 14 天；取最早的；今天 > 期限 = 超期（红、置顶、写超了几天）。
- 到货率：近 90 天确认的（不含取消）→ 已到货 ÷ 总数，同时列出 在途未超期 / 超期 / 待发注 / 关闭未到齐 各几件。
- 同 JAN 已有未完成申请（待确认/待发注/在途/超期）→ 提交时挡下并说是哪张。

## 页面
顶部数字：待确认 · 待发注 · 在途 · 🔴 超期 · 到货率。四块：
1. ➕ 提申请：表格多行填 JAN·数量·备注（商品名可空，NST 有档就自动带）；申请人 = 飞书登录名（密码登录 = 「密码登录」）。
2. 📋 待确认：可改 仕入先（NST 仕入先主档）· 单价 · 数量，勾选 →「✅ 确认」/「🗑️ 取消」。
3. 📦 发注书：待发注里勾选 → 日付/従業員/部門/場所/メモ/税率 fallback（与 page10 同）→ NST 订货单 CSV（仕入先各一个外部 ID、合并一个文件）；
   NST 未建档的 JAN 列出来并提示先去 page15 建档。
4. 🚚 到货跟踪：超期 → 部分到货 → 在途 → 待发注 排序，已完成默认折叠；显示 PO 号·发注数·入荷数·期限·超几天。
