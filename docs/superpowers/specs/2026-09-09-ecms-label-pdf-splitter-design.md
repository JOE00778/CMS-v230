# ECMS 面单合集拆分工具设计

日期：2026-09-09
状态：已获 Boss 设计确认，等待书面规格复核

## 1. 目标

在 CMS 的“🛠️ 工具”中新增“✂️ 面单合集拆分”。用户上传一份一页一张的 ECMS 面单合集 PDF 后，系统从每页固定位置提取 13 位面单单号，将原始页面拆成独立 PDF，并生成一个 ZIP 供整批下载。

示例页面必须输出 `6102821704186.pdf`。拆分过程必须保持原页面尺寸、矢量内容和打印质量，不得重新生成整张面单。

## 2. 范围

### 2.1 包含

- 一次上传一份 PDF。
- 输入 PDF 固定为一页一张 ECMS 面单。
- 单号位于每页中部偏右的统一位置，格式为 13 位数字。
- 优先读取固定区域的 PDF 文字层。
- 文字层没有唯一单号时，对同一区域运行本地 RapidOCR。
- 每个成功页面输出一个以单号命名的单页 PDF。
- 所有页面进入同一个 ZIP；ZIP 内附 `处理结果.csv`。
- 页面显示总页数、成功数、识别失败数和重复数。
- 所有数据仅在 CMS 进程内存中处理。

### 2.2 不包含

- 不处理一页多张面单。
- 不处理 ECMS 以外、版式位置不同的面单。
- 不读取条形码中的 `ECLBF...` 编号作为文件名。
- 不修改、缩放、旋转或重排原始 PDF 页面。
- 不把面单上传到 Gemini、云 OCR 或其他第三方服务。
- 不把客户信息、PDF 内容或 OCR 全文写入数据库、文件日志或审计日志。
- 不修改 `pages/41_📮_ECMS发货.py`。
- 本规格不授权 GitHub push、元川机部署或线上重启。

## 3. 用户流程

1. 用户打开“🛠️ 工具 → ✂️ 面单合集拆分”。
2. 用户上传一个 `.pdf` 文件。
3. 页面显示文件名和 PDF 总页数。
4. 用户点击“开始拆分”。
5. CMS 逐页提取单号并复制原始页面。
6. 页面显示处理汇总和异常页明细。
7. 用户点击“整批下载 ZIP”。

处理失败时，页面必须显示明确原因。页面不得把部分成功结果描述为全部成功。

## 4. 架构与文件

### 4.1 核心模块

新增 `shared/ecms_label_splitter.py`，只负责 PDF 处理，不依赖 Streamlit。它提供一个批处理入口，输入 PDF 字节，输出处理汇总、ZIP 字节和逐页结果。

模块内部划分为四个单一职责单元：

1. 固定区域提取：根据页面宽高计算相对坐标，读取中部偏右区域。
2. 单号识别：先读文字层，再对固定区域做本地 OCR。
3. 页面复制：从原 PDF 原样复制指定页面到新的单页 PDF。
4. ZIP 打包：生成成功文件、异常文件和结果清单。

PDF 读取、区域渲染和页面复制统一使用 PyMuPDF。OCR 复用 CMS 已安装的 `rapidocr-onnxruntime`。

### 4.2 CMS 页面

新增 `pages/42_✂️_面单合集拆分.py`，负责：

- 登录守门、主题和语言选择。
- PDF 上传与基本校验。
- 启动处理并显示进度。
- 展示汇总指标和异常页列表。
- 提供 ZIP 下载按钮。

页面不直接实现 PDF 或 OCR 逻辑。

### 4.3 导航与依赖

- 修改 `shared/i18n.py`，把新页面登记到 `_NAV_GROUPS` 的“🛠️ 工具”分组，并补充日文显示文案。
- 修改 `requirements.txt`，增加生产容器使用的 PyMuPDF 依赖。
- 修改 `pyproject.toml`，保持本地开发环境与生产依赖一致。
- 新增 `tests/test_ecms_label_splitter.py`。

## 5. 单号识别规则

### 5.1 固定区域

识别区域使用相对坐标定义，避免不同 PDF 页面尺寸造成绝对像素偏移。初始区域覆盖示例图中单号所在的中部偏右位置，并保留少量四周余量。

最终坐标必须用实际“0909面单合集.pdf”校准。截图只能证明版式意图，不能证明原 PDF 的坐标和文字层结构。

### 5.2 文字层优先

系统先从固定区域读取 PDF 文字。候选必须严格匹配独立的 13 位数字：

```text
(?<!\d)\d{13}(?!\d)
```

固定区域只有一个候选时，识别成功。没有候选或存在多个候选时，进入 OCR 兜底。

### 5.3 本地 OCR 兜底

系统仅把固定区域渲染为高清图片，并交给本地 RapidOCR。系统从 OCR 行文本中寻找唯一的 13 位数字。

系统不得自动把 `O`、`I`、`S` 等字母纠正成数字。这类猜测可能生成错误文件名，应当作为识别失败交给用户检查。

### 5.4 唯一性

- 一个候选：成功。
- 零个候选：识别失败。
- 多个不同候选：识别失败。
- 单号与前面成功页面重复：重复单号。

## 6. 输出规则

ZIP 内目录结构：

```text
面单拆分-20260909-153000.zip
├── 6102821704186.pdf
├── 6102821704187.pdf
├── 识别失败/
│   ├── 第003页.pdf
│   └── 重复单号-第006页.pdf
└── 处理结果.csv
```

`处理结果.csv` 使用 UTF-8 with BOM，至少包含：

- `page_number`
- `status`
- `tracking_number`
- `recognition_method`
- `output_path`
- `reason`

状态固定为：

- `success`
- `unrecognized`
- `ambiguous`
- `duplicate`

总页数必须等于所有状态的页面数之和。ZIP 必须保留失败和重复页面，确保输入页面不丢失。

## 7. 错误处理与安全

- 非 PDF、空文件、加密 PDF、损坏 PDF：停止处理并显示明确错误。
- 零页 PDF：停止处理并显示明确错误。
- 单页异常：记录失败后继续处理后续页面。
- OCR 组件不可用：文字层识别继续工作；需要 OCR 的页面标为失败，并显示组件不可用。
- ZIP 生成失败：不显示下载按钮，并报告失败。
- 异常信息不得包含客户姓名、电话、地址、OCR 全文或 PDF 原文。
- 上传字节、单页 PDF、裁剪图和 ZIP 只保存在当前 Streamlit 会话内存中，不写服务器磁盘。

## 8. 测试与验收

### 8.1 自动测试

用程序生成不含真实客户数据的合成 PDF，覆盖：

1. 多页文字层 PDF 能按单号拆分。
2. 每个输出文件只有一页。
3. 输出页面尺寸与输入页面一致。
4. 文字层失败时进入 OCR 兜底。
5. OCR 返回唯一 13 位数字时成功。
6. 无单号、多个单号和非 13 位数字均失败。
7. 重复单号不覆盖先前文件。
8. ZIP 保留所有输入页面。
9. `处理结果.csv` 行数等于输入页数。
10. 错误信息不泄漏页面全文。

### 8.2 静态与回归验证

- 用 Python 3.11 解析新页面语法。
- 检查新页面已登记到 `_NAV_GROUPS`。
- 运行专项测试。
- 运行 CMS 全量 pytest，并报告 `ok`、`fail` 和 `skipped`。

### 8.3 实际文件验收

用户提供实际“0909面单合集.pdf”后执行最终验收：

- 输入页数与 ZIP 中逐页结果数一致。
- 抽查成功文件名与页面可见单号一致。
- 示例页输出 `6102821704186.pdf`。
- PDF 可打开，页面尺寸、方向和清晰度不变。
- ZIP 可正常下载和解压。

在实际文件验收完成前，状态只能写“代码测试完成，真实文件待验”。
